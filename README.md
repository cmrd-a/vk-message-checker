# VK Message Checker

Расширение для Chrome (Manifest V3), которое показывает счётчик непрочитанных сообщений VK на иконке панели инструментов и позволяет быстро открыть VK. Структура и большая часть механики (иконка, тёмная тема, уведомления, тихие часы, локализация) скопированы и адаптированы из [ya-mail-checker](https://github.com/cmrd-a/ya-mail-checker) — того же автора расширения для Яндекс.Почты.

## Как это работает

Официальный API VK для чтения чужих сообщений (`messages.getConversations` и т.п.) требует OAuth‑токен, выданный **Standalone**‑приложению — а такие приложения ВК больше не регистрирует. Но сам `vk.ru/im` тоже не «читает разметку» — он вызывает тот же самый `api.vk.ru/method/*`, используя `access_token`, который встроен в HTML страницы (`window.vk.webToken.access_token`, привязан к сессионным cookie, живёт несколько часов). Расширение повторяет ровно то же самое:

1. `GET vk.ru/im` с cookie пользователя (`credentials: "include"`) → достаёт `access_token` из инлайн‑скрипта страницы.
2. `POST api.vk.ru/method/messages.getDiff` с этим токеном → `response.counters.messages_folders[].total_count` — счётчик непрочитанных (для бейджа).
3. `POST api.vk.ru/method/messages.getItems` с этим токеном → список диалогов с превью последнего сообщения (для попапа).

Это реверс‑инжиниринг реального запроса из HAR‑захвата залогиненной сессии `vk.ru/im`, а не документированный/поддерживаемый API — VK может изменить эту механику в любой момент.

### Не до конца подтверждено

- **Семантика `messages_folders`.** В захваченной сессии все счётчики были нулевые (нет непрочитанных), поэтому не на чем проверить, какой именно `folder_id` соответствует «основным» непрочитанным, а какой — заявкам/архиву/и т.п. Сейчас счётчик — это сумма `total_count` по всем папкам **плюс** `channels.total_count`. Если это число не совпадает с тем, что показывает сам VK, — смотреть сюда в первую очередь: `js/vk.js`, `parseUnreadCount`.
- **Ссылка на диалог в попапе** (`vk.ru/im?sel=<id>`) — стандартный для VK паттерн диплинка, но конкретно в захваченном трафике не встречался (там просто загружали `/im` целиком, без перехода в конкретный диалог).
- **Какой элемент списка считается «самым новым».** Уведомление берёт первый непрочитанный элемент из ответа `messages.getItems`, предполагая, что VK возвращает диалоги отсортированными по последней активности (это стандартное поведение мессенджеров и похоже на правду по полю `sort_id` в ответе) — но отдельно это не проверялось.

Раньше `fields` и `start_from` в `messages.getItems` были урезаны/убраны для краткости — из‑за этого список в попапе приходил пустым, хотя счётчик работал. Сейчас оба параметра скопированы из захваченного запроса дословно.

**Аватары.** Фото отправителя берётся из `photo_100`/`photo_50` в ответе `messages.getItems` (домен `*.vkuserphoto.ru`, добавлен в `host_permissions`). В попапе это просто `<img src="...">` — работает без хитростей. В desktop‑уведомлениях иначе: `chrome.notifications` **не поддерживает** внешние `https://` ссылки в `iconUrl` (только `data:`/`blob:`/локальные пути расширения — в отличие, например, от Firefox), поэтому для уведомлений фото сначала скачивается самим расширением и конвертируется в `data:` URL (`fetchAvatarDataURL` в `js/background.js`).

Если что‑то из этого не работает как ожидается — пришли новый HAR с реальным непрочитанным сообщением, разберёмся точнее.

## Возможности

- Счётчик непрочитанных на бейдже иконки, цветная/серая иконка для состояний «есть сообщения» / «не авторизован» / «нет соединения», адаптация под тёмную/светлую тему панели.
- Периодическая фоновая проверка через `chrome.alarms` с настраиваемым интервалом (или «никогда»).
- Индикатор проверки (синий бейдж `…`) и понятные подсказки‑тултипы.
- Поведение по клику: меню‑попап **или** одиночный клик = открыть VK / двойной = проверить сейчас.
- Попап: реальная фотография отправителя (или цветной кружок с инициалом, если фото нет/не загрузилось), счётчик непрочитанных рядом с заголовком, время последней проверки внизу; клик по сообщению открывает диалог. Показывать только непрочитанные — настраивается (по умолчанию включено).
- Уведомления показывают реальный текст, отправителя и его фото (а не просто «Непрочитанных: N»); если между проверками пришли сообщения от нескольких разных отправителей — своё отдельное уведомление для каждого, без ограничения по количеству и без сводки вместо них.
- Мигание значка на панели при появлении новых сообщений (можно отключить).
- Звук уведомления на выбор: системный, два синтезированных тона («перезвон» / «колокольчик») или без звука.
- «Тихие часы» — на выбранный интервал времени уведомления и звук отключаются (счётчик на бейдже продолжает обновляться).
- Гибкое открытие VK: переиспользование существующей вкладки, текущая/новая/фоновая вкладка.
- Локализация интерфейса: язык выбирается **в настройках расширения** (Авто / English / Русский), а не зависит от языка браузера.

Пока не реализовано (и не планируется без нового HAR‑захвата с реальным примером): пометить сообщение прочитанным, удалить, ответить прямо из попапа.

## Требования

- Chrome **116+**.

## Установка (режим разработчика)

1. Открой `chrome://extensions`.
2. Включи **Режим разработчика** (Developer mode) в правом верхнем углу.
3. Нажми **Загрузить распакованное расширение** (Load unpacked) и выбери папку проекта.
4. Иконка появится на панели инструментов. Авторизуйся в VK в этом же браузере.

После изменений в коде нажми «Обновить» (↻) на карточке расширения в `chrome://extensions`.

## Настройки

Открываются через меню‑попап → шестерёнка или со страницы `chrome://extensions`.

- **Язык** — язык интерфейса (Авто / English / Русский).
- **Проверка сообщений** — показывать в попапе только непрочитанные.
- **Уведомления** — показывать desktop‑уведомление, мигать значком, звук уведомления, «тихие часы» с диапазоном времени.
- **Автопроверка** — интервал фоновой проверки (от 1 минуты до «никогда»).
- **Иконка на панели** — показывать ли счётчик; меню по клику или одиночный/двойной клик.
- **Открытие VK** — сбрасывать ли счётчик при открытии, переиспользовать вкладку, куда открывать VK.

## Сборка пакета

```bash
./build.sh
```

или на Windows:

```powershell
.\build.ps1
```

Скрипт собирает `dist/vk-message-checker-<версия>.zip` только из нужных в рантайме файлов (`manifest.json`, `_locales`, `css`, `html`, `js`, `icons`).

## Структура проекта

```
manifest.json            # Манифест MV3 (service worker, action, host_permissions)
_locales/                # Переводы (en, ru) в формате chrome.i18n messages.json
icons/                   # Иконки расширения (сгенерированы процедурно, не логотип VK)
css/                     # Стили страниц (options.css, popup.css)
html/                    # Разметка страниц (options.html, popup.html, offscreen.html)
js/
  background.js          # Service worker: проверка сообщений, иконка, расписание, открытие
  vk.js                  # URL VK, извлечение access_token, вызовы api.vk.ru и разбор ответов
  i18n.js                # Загрузчик локали по выбору пользователя + локализация страниц
  options.js              # Логика страницы настроек
  popup.js                # Логика меню‑попапа
  offscreen.js             # Offscreen‑страница: тема браузера + синтез звуков уведомлений
tests/
  vk.test.js              # Тесты извлечения токена и разбора ответов API
  background.test.js      # Тесты resolveLang/isQuietHours/fetchText/checkNow
```

## Ограничения

- Механика в `js/vk.js` — реверс‑инжиниринг недокументированного поведения `vk.ru/im`, не официальный API. VK может изменить её без предупреждения.
- Как и в ya-mail-checker, реальные действия с сообщениями (пометить прочитанным, удалить и т.п.) не реализованы, пока их эндпоинты не будут найдены в реальном захвате трафика.
- Требуется активная сессия (авторизация) в VK в том же профиле браузера.
